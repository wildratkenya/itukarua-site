# Git Hygiene

## Never stage these

| Path | Why |
| --- | --- |
| `public/sitemap.xml` | Regenerated by `prebuild`; committing it churns diffs. |
| `public/robots.txt` | Same — generated. |
| `supabase/.temp/cli-latest` | Supabase CLI scratch file. |
| `src/components/itukarua/HeroSection.tsx` | Local working copy / WIP; not part of the app commits. |
| `docs/node_modules/` | Covered by the root `.gitignore` `node_modules` pattern, but confirm before staging. |

Stage only the files you intentionally changed:

```bash
git status
git add <specific files...>   # avoid `git add -A` if generated files are dirty
git diff --staged
git commit -m "type(scope): summary"
```

## Commit message style

Conventional, verb-led, lowercase scope, e.g.:

```
fix(jobseeker plans): tie Free/Premium features to reality
```

Recent history: `dd4e114` (the Free/Premium audit), plus the employer/advert/corporate work.

## Rules of the road

- **The Free/Premium audit was client-side only.** Do not add migrations to fix gating unless the
  work explicitly asks for server-side enforcement.
- **Do not modify app source to make docs easier.** `docs/` is documentation only; it has its own
  `package.json` and never imports from `src/`.
- **Run the checks before pushing:**
  ```bash
  npx tsc -p tsconfig.app.json --noEmit
  npm run build
  ```
- **Don't commit secrets.** `.env.vercel` includes Vercel system tokens; never copy them into
  tracked files or docs.
- Prefer `git add <paths>` over `git add -A` so generated artifacts never sneak in.

## Deployment coupling

`main` auto-deploys to `https://itukarua3.vercel.app`. Treat every push to `main` as a production
release — no WIP commits on `main`.
