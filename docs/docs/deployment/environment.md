# Environment Variables

The app reads a small set of **build-time** `VITE_*` variables. Each has a hardcoded fallback so
the app runs even with no `.env`, which is why the happy path needs no env file.

| Variable | Used by | Fallback / default |
| --- | --- | --- |
| `VITE_SITE_URL` | `src/lib/siteConfig.ts` (SEO, sitemap, canonical URLs) | `https://itukarua3.vercel.app` |
| `VITE_SUPABASE_URL` | `src/lib/supabase.ts` | hardcoded project URL |
| `VITE_SUPABASE_ANON_KEY` | `src/lib/supabase.ts` | hardcoded anon key |

```ts
// src/lib/supabase.ts
export const supabaseUrl = import.meta.env.VITE_SUPABASE_URL || SUPABASE_URL;
export const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY || SUPABASE_ANON_KEY;
```

```ts
// src/lib/siteConfig.ts
export const SITE_URL =
  (import.meta.env.VITE_SITE_URL as string | undefined)?.trim() || 'https://itukarua3.vercel.app';
export const SITE_NAME = 'Itukarua';
```

## Files present in the repo

- `.env` / `.env.local` — developer-local overrides (fallback values already work if absent).
- `.env.vercel` — **generated by the Vercel CLI**, contains `VITE_SUPABASE_URL` +
  `VITE_SUPABASE_ANON_KEY` and Vercel system vars (including a short-lived `VERCEL_OIDC_TOKEN`).
  Treat it as environment-managed, not authored.

## Notes and cautions

- These are **build-time** vars (Vite inlines `import.meta.env.*`). Changing them requires a
  rebuild/redeploy — setting them at runtime does nothing.
- The Supabase **anon key is public by design** (it ships in the client bundle). Security depends
  on Postgres **RLS**, not on hiding this key. Never put the **service-role key** in any `VITE_`
  variable — it would be exposed to every visitor. Service-role work belongs in Edge Functions
  where the key is a server-side secret.
- `VITE_SITE_URL` influences canonical tags and `scripts/generate-seo.mjs`, so set it correctly
  before a production build if you move domains.
